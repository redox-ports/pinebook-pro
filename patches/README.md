# Upstream patches

Files here are applied to upstream Redox repositories when a port-specific fix is
unavoidable. Each patch records the target repository, the base commit it was
generated against, and the reason.

| `kernel-gicv3-root-interrupts.patch`         | `redox-os/kernel`     | `719e8f5c`  | The RK3399 DT (U-Boot `rk3399.dtsi`) puts `interrupts = <GIC_PPI 9 ...>` on the root GICv3 node. `src/dtb/irqchip.rs` parses `interrupts` with `Node::property::<Interrupts>()`, whose parser requires the interrupt parent's `#interrupt-cells`; a root controller has none, so the kernel panics with `MissingRequiredProperty("interrupt-cells")` during IRQ chip init (experiment 4). The patch parses `interrupts` only for controllers that declare an explicit `interrupt-parent` (or `interrupts-extended`); root controllers are then handled as roots, as intended.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `kernel-inherited-interrupt-parent.patch`    | `redox-os/kernel`     | `719e8f5c`  | The DT spec makes `interrupt-parent` inheritable, but the pinned `fdt` crate resolves a missing `interrupt-parent` to the immediate parent node and then looks for `#interrupt-cells` there. On RK3399 only the root node carries `interrupt-parent = <&gic>`, so parsing `/timer`'s `interrupts` panics with the same error during generic-timer init. The patch resolves the inherited parent by walking ancestors, parses the legacy `interrupts` property directly (1–4 cells; the GICv3 fourth PPI-partition cell is ignored for now), and updates the four `get_interrupt` call sites to pass the `Fdt`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `kernel-uart-16550-rx-irq.patch`             | `redox-os/kernel`     | `719e8f5c`  | Two driver bugs that keep the RK3399 UART2 console from receiving input (experiment 5). (1) The NS16550 loopback self-test fails on this board, and `uart_16550::init()` returned early on failure — skipping the final `modem_ctrl = 0x0F` / `int_en = 0x01` writes, so the port kept loopback enabled and `IER = 0`. (2) `init()` enabled the FIFO with a 14-byte receive threshold (`FCR = 0xC7`); one keystroke never reaches it and this UART has no usable character-timeout interrupt, so no receive interrupt is ever raised (Linux 8250 uses a one-character trigger). The patch records the self-test outcome instead of returning early, always restores MCR/IER, logs the failure, uses `FCR = 0x07`, and implements `SerialKind::enable_irq` for the NS16550 variants (previously a documented TODO no-op).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `kernel-gicv3-spi-group1.patch`              | `redox-os/kernel`     | `719e8f5c`  | `GicDistIf::init()` never programmed `GICD_IGROUPR`, `GICD_IROUTER`, and — the decisive bug found with register dumps (experiment 5, iterations 4–6) — overwrote `GICD_CTLR` with `0x3`, wiping the firmware-set `ARE_S` bit (`0x20`). With affinity routing dropped on one side, Group 1 NS SPIs (UART2, IRQ 132) stayed pending at the distributor forever and never reached the CPU, while the timer PPI kept working. The patch switches `GICD_CTLR` to read-modify-write (`ctlr` changed from 0x3 to 0x23), marks every SPI non-secure Group 1, and routes every SPI to the boot CPU (`IROUTER = 0`, affinity 0.0.0.0). All writes are harmless on GICv2 (RAZ/WI) and on a single-security-state GIC.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `kernel-framebuffer-16bpp.patch`             | `redox-os/kernel`     | `719e8f5c`  | The firmware framebuffer is not always 32 bits per pixel: U-Boot v2021.07 programs the RK3399 VOP in RGB565 for the eDP panel (`rk_vop.c` forces `VIDEO_BPP16` for `VOP_MODE_EDP`) and reports `PixelBitMask` `0xf800/0x07e0/0x001f`. `graphical_debug` wrote 32-bit ARGB pixels into that surface and reserved `stride*height*4` bytes, which appeared on the panel as a black/yellow dither (experiment 7). The patch reads `FRAMEBUFFER_BPP` (default 32, so existing platforms are unchanged), converts glyph colours to RGB565, clamps the last text row to the display height and reserves the real size.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `kernel-signal-delivery-after-syscall.patch` | `redox-os/kernel`     | `719e8f5c`  | `signal_handler()` runs from `sched_yield()` and from `context::switch::tick()`, i.e. while a syscall is still executing. It records `regs.sig_archdep_reg()` (x0) and the resume address (the instruction after `svc`) for the userspace signal trampoline, but the arch syscall epilogue writes the result into `scratch.x0` only after `syscall()` returns. A signal delivered in that window therefore saved the syscall *argument* as its return value, and `sigreturn` made the caller resume with it: relibc's `Sys::verify()` yield was entered with x0 = -1 and resumed with x0 = -1, so uutils binaries took the `b.hs -> brk #1` abort path at startup and died silently (experiment 10; the trap site was pinned by deriving the module bases from the dump: executable 0x1000, `libc.so` 0xa80000). The patch makes `signal_handler()` refuse to run while `percpu.inside_syscall` is set (`being_sigkilled` is still honoured first) and calls it from the aarch64 syscall epilogue right after `stack.scratch.x0 = ret`. Timer-tick delivery in userspace is unchanged.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `bootloader-gop-bpp.patch`                   | `redox-os/bootloader` | `f3d9261`   | `OsVideoMode` now carries `bpp`, derived after `SetMode` from `Mode.Info.PixelFormat`: 32 for the two 8-bit-per-channel formats and the top bit of the R/G/B masks for `PixelBitMask` (`0xffff` → 16). It is exported as `FRAMEBUFFER_BPP` in the boot environment (same blob as the other `FRAMEBUFFER_*` keys) and used for the framebuffer mapping size. Unknown formats export 0, which consumers treat as 32bpp; VBE keeps 32. The same patch makes the mode menu non-blocking: `Os` gained `get_key_timeout(ms)` (default falls back to the old blocking `get_key()`), the UEFI implementation polls `ReadKeyStroke` against a deadline from `RuntimeServices.GetTime` with a bounded-spin fallback for boards whose clock never ticks (no RTC driver on the Pinebook Pro), and `select_mode` boots the highlighted mode after 3 s. Apply from the repo root.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `base-pinebook-pro.patch`                    | `redox-os/base`       | `8f576d27`  | Pinebook Pro initfs additions (experiments 4-8). (1) `debugsh`, a static initfs daemon on the kernel `debug` scheme, provides the interim serial console (line discipline, ls/cat/echo>/hexdump/env/exec/reboot via PSCI, cwd set to `/scheme/initfs`, `ls /` maps to `/scheme`) while the root filesystem cannot mount; also stops `hwd` spawning `pcid` on aarch64 and gates both `pcid-spawner` services to x86/x86_64 (`pcid`'s PCI fallback is `todo!()` there). (2) `dwmmcd`, a static FIFO/PIO polling driver for the RK3399 DW MMC microSD controller (`fe320000`, matched by compatible string plus reg address so the SDIO controller and the baseline-OS eMMC are never probed); inherits U-Boot's CRU clocking, reprograms only `CLKDIV` via the CIU clock-update command for the identification window, registers the `disk.mmc` scheme before `50_rootfs.service`, and mirrors bring-up logs to `/scheme/debug`. (3) `vesad` honours `FRAMEBUFFER_BPP` (experiment 7): the firmware framebuffer is RGB565 on this board, so it maps the real size, converts ARGB8888 client buffers to RGB565 on presentation, and uses the same pixel size when clearing. (4) `ohcid`, a static initfs OHCI host driver for the RK3399 USB2 ports (experiment 8): U-Boot brings up only the OHCI halves of the EHCI/OHCI pairs, so the internal hub with the keyboard/touchpad runs at full speed there; the driver polls (no interrupts, no `nanosleep`), uses `common::dma` for descriptors, enumerates one level of hub, switches a boot keyboard to the boot protocol and feeds `inputd`. Supersedes `base-initfs-debug-console.patch` (same base commit, contents folded in). Apply from `recipes/core/base/source`. |
| `relibc-cxa-reentrancy.patch`                | `redox-os/relibc`     | `b83feabc`  | `__cxa_thread_finalize()` held the thread-local `DTORS` `RefCell` borrow across the destructor calls, so a destructor that registers another thread-atexit handler re-entered `__cxa_thread_atexit_impl()` and panicked with `RefCell already borrowed` at `src/cxa.rs:84` (hardware: every uutils binary, e.g. `rm -rf /tmp`, `mkdir`; experiment 10). `relibc_panic` then `abort()`s with `brk #1` and buffered stdout is lost, which is why some applets appeared to die without any output. `__cxa_finalize()` had the same shape with its spin mutex (destructors called while the lock is held). The patch pops one thread-atexit entry under a scoped borrow and runs it after the borrow is released (LIFO preserved; handlers registered by a destructor run in the next iteration), and collects the atexit entries under the lock, drops it, then runs them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
