# Upstream patches

Files here are applied to upstream Redox repositories when a port-specific fix is
unavoidable. Each patch records the target repository, the base commit it was
generated against, and the reason.

| File                                      | Target repo       | Base commit | Reason                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------------------------------- | ----------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `kernel-gicv3-root-interrupts.patch`      | `redox-os/kernel` | `719e8f5c`  | The RK3399 DT (U-Boot `rk3399.dtsi`) puts `interrupts = <GIC_PPI 9 ...>` on the root GICv3 node. `src/dtb/irqchip.rs` parses `interrupts` with `Node::property::<Interrupts>()`, whose parser requires the interrupt parent's `#interrupt-cells`; a root controller has none, so the kernel panics with `MissingRequiredProperty("interrupt-cells")` during IRQ chip init (experiment 4). The patch parses `interrupts` only for controllers that declare an explicit `interrupt-parent` (or `interrupts-extended`); root controllers are then handled as roots, as intended.                                                                                                                                                                                                                                            |
| `kernel-inherited-interrupt-parent.patch` | `redox-os/kernel` | `719e8f5c`  | The DT spec makes `interrupt-parent` inheritable, but the pinned `fdt` crate resolves a missing `interrupt-parent` to the immediate parent node and then looks for `#interrupt-cells` there. On RK3399 only the root node carries `interrupt-parent = <&gic>`, so parsing `/timer`'s `interrupts` panics with the same error during generic-timer init. The patch resolves the inherited parent by walking ancestors, parses the legacy `interrupts` property directly (1–4 cells; the GICv3 fourth PPI-partition cell is ignored for now), and updates the four `get_interrupt` call sites to pass the `Fdt`.                                                                                                                                                                                                           |
| `kernel-uart-16550-rx-irq.patch`          | `redox-os/kernel` | `719e8f5c`  | Two driver bugs that keep the RK3399 UART2 console from receiving input (experiment 5). (1) The NS16550 loopback self-test fails on this board, and `uart_16550::init()` returned early on failure — skipping the final `modem_ctrl = 0x0F` / `int_en = 0x01` writes, so the port kept loopback enabled and `IER = 0`. (2) `init()` enabled the FIFO with a 14-byte receive threshold (`FCR = 0xC7`); one keystroke never reaches it and this UART has no usable character-timeout interrupt, so no receive interrupt is ever raised (Linux 8250 uses a one-character trigger). The patch records the self-test outcome instead of returning early, always restores MCR/IER, logs the failure, uses `FCR = 0x07`, and implements `SerialKind::enable_irq` for the NS16550 variants (previously a documented TODO no-op). |
| `kernel-gicv3-spi-group1.patch`           | `redox-os/kernel` | `719e8f5c`  | `GicDistIf::init()` never programmed `GICD_IGROUPR`, `GICD_IROUTER`, and — the decisive bug found with register dumps (experiment 5, iterations 4–6) — overwrote `GICD_CTLR` with `0x3`, wiping the firmware-set `ARE_S` bit (`0x20`). With affinity routing dropped on one side, Group 1 NS SPIs (UART2, IRQ 132) stayed pending at the distributor forever and never reached the CPU, while the timer PPI kept working. The patch switches `GICD_CTLR` to read-modify-write (`ctlr | 0x3` → `0x23`), marks every SPI non-secure Group 1, and routes every SPI to the boot CPU (`IROUTER = 0`, affinity 0.0.0.0). All writes are harmless on GICv2 (RAZ/WI) and on a single-security-state GIC. |
| `base-initfs-debug-console.patch`         | `redox-os/base`   | `8f576d27`  | Interim serial console (experiment 5): boot stops in the initfs phase because the microSD (DW MMC) driver does not exist yet, so there is no root filesystem, shell, or login. Adds `debugsh`, a small static initfs daemon that opens the kernel `debug` scheme (`/scheme/debug`), provides UART echo/backspace, and a few built-ins (`ls`, `cat`, `echo >`, `hexdump`, `env`, `exec`) so schemes and initfs binaries can be exercised over UART without storage. Also gates `pcid` spawning to non-aarch64 (`hwd` spawns `pcid` directly, bypassing init services) and gates both `pcid-spawner` services to x86/x86_64 — `pcid`'s PCI 3.0 configuration-space fallback is `todo!()` on aarch64 and panics (experiments 4–5). Apply from `recipes/core/base/source`.                                                   |

Temporary bring-up instrumentation (UART markers) lives in `debug/` and is **not**
intended for upstream.
